# 26.0.0-dev.2

Changes since `0.10.0`.

## New Features

### Driving the running app

- **`aimer input`**: sends a click, key or gesture to the app a run session launched, from a shell or a script. Subcommands include `click`, `move`, `drag`, `scroll`, `key`, `type`, a touch `tap`, and `send` for raw protocol lines.
    - It sends to the only live session; pass `--session <id>` (see `aimer sessions`) or `--project` when there are several.
- **MCP input tools**: `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click`, `mouse_move`, `left_click_drag`, `scroll`, `key` and `type` drive the app like a mouse and keyboard, in the vocabulary of the computer-use tools. Coordinates are logical pixels from the top-left corner of the app's window.
    - The mouse glides along a curved, eased path instead of jumping, and a command sent mid-glide retargets it.
- **Touch tools** `tap`, `swipe` and `pinch` for apps on a phone or tablet.
- **`send_input`**: sends raw `aimer_prendre` protocol lines for events the tools above do not cover, such as `back`, `link`, `menu`, `file-drop`, `preedit` and `quit`. The whole request is checked before anything is sent.
- `aimer run` now asks the app it launches to accept input, on macOS, desktop and iOS (Simulator and device). A debug build starts the input server; a release build never does. Nothing needs to change in the app.
    - On an iOS device the CLI reaches the app through the `devicectl` tunnel address, wired or wireless.
    - Set `AIMER_PRENDRE=0` for `aimer run` to turn it off.
    - Android is not wired yet.

### Commands

- Added `aimer update`: updates the CLI to the latest release.
- Added `aimer components`: manages the build environment, including the Aimer NDK.

## Fixes

- MCP: tracing logs now go to stderr. A warning or `--verbose` / `RUST_LOG` output on stdout corrupted the JSON-RPC stream and made clients drop the server.
- MCP: every Rust call after the first no longer hangs. Reads reported by the file watchers were treated as edits, which forced a full workspace reload after reading any `Cargo.toml` or `build.rs`, and re-indexed `.rs` files that had not changed. Reads and metadata-only changes are now ignored, and `build.rs` counts as a build script only next to a `Cargo.toml`.
- MCP: `get_project_metadata` now fails with `isError: true` when `cargo metadata` is unavailable, with the exit code, Cargo's message and an offline hint when the offline Cargo policy caused it.
- MCP: tool schemas are now portable. Optional parameters collapse to their single non-null type, and `preview_manifest_edit`'s `value` declares its TOML-compatible JSON types, so single-type dialects such as Gemini function declarations accept them. Tool names, argument names and required lists are unchanged.
- Fixed path separator handling (`/` and `\`) in the `components` command on Windows, Unix and other platforms.

## Improvement

- `inspect_file` text searches take `query`, matching `search_text`. `pattern` is still accepted as an alias.
- While a session is driven, the app shows a `driven by aimer-cli` badge and draws where each injected pointer and finger is, so a screenshot shows what the agent did. A debug build only.
- Input tools are documented in `docs/MCP.md` under "Driving the app", and listed in the `aimer-rust` skill.

## Changes

- Input tools run one at a time as session operations, like `restart_project`, because they act on the running app and not on the workspace files.
- Removed the hot-reload crate (`aimer_hot_reload`). The shared configuration now lives in `aimer_config`.
- Added the `aimer_prendre` client dependency, used to send input to a running app.
- Updated the CI/CD workflow.
